What DJ pushed

PR #2 makes report reconciliation the main demo. A customer disputes a monthly total ($1,550 shown vs $1,150 expected). The approved rules show both are wrong and the defensible figure is $1,250. Ten synthetic cases cover code defects, config defects, expected behavior, and three cases where the right answer is to stop. The PR includes a deterministic rules engine, read-only MCP tools, a 30-trial benchmark harness, and an offline HTML walkthrough.

Everything offline reproduced on this machine: 40/40 tests, the rules workflow at 10/10, and the regression fails on the seed code, fails on the -abs() fix, and passes on the reference. The live Claude comparison had never run. The docs say it was blocked because Claude Code was not authenticated.

What this tells us

Benchmark

The test is too easy to compare the conditions

With ten short documents, Opus 5.5 gets every case right however the evidence reaches it. That includes the traps: the -abs() fix, the pending Jira request (DH-303, passed in all three conditions), and the cancelling errors in DH-310. The evaluation protocol predicted this ("direct context may be faster than retrieval"), and now it's measured. The current fixture can show that a model reaches the right business decision. It cannot show that retrieval or the workflow tool beats pasting the documents into the prompt.

Scoring

The strict check penalizes the tool conditions for the same habit

In provided, every document counts as "observed," so extra citations are free. Opus added sources nobody needed in all 10 provided runs (DH-188 in 9 of them). In retrieval and workflow, citing anything not fetched in full fails the trial. All three failures were extra, non-required sources that the model cited to say "this doesn't apply" (DH-204, REPORT-STD-SEP, FEED-ATLAS-1/2, REPORT-STD-OCT). No required source was missing in any trial. The 10 / 9 / 8 ranking comes from this rule, not from a difference in capability.

Operational

The workflow tool's measurable value is efficiency and auditability

Compared with retrieval alone, the deterministic tool halved the tool calls (3.2 vs 6.3), cut cost by about 24% and cut median time by about 20%, with identical correctness. Every workflow answer also carries row-level arithmetic and hashed source snapshots from code, not from the model. That holds up in a meeting. "More accurate" does not, on this evidence.

Bug, fixed on branch

The runner would have silently tested Sonnet

The runner passed the model from ~/.claude/settings.json straight to claude --print. Here that value is opusplan, which runs Sonnet outside plan mode, so "default" runs would not have been Opus. It also overrides ANTHROPIC_MODEL. I added --model to preflight, agent and benchmark. All 40 tests pass, and the traces confirm claude-opus-5-5 in all 30 trials.

Adapter

The live harness works as designed

On its first real run against an authenticated provider, the harness behaved as designed: no timeouts, no denied tools, no schema failures, frozen hashes held for all 30 trials, and every attempt was saved to disk before the next one started. The quality of the explanations looks good on a spot check. For example, DH-304's stop names the draft contract and routes to Data Integrations. Formal human review is still pending.
